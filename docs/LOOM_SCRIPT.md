# Loom walkthrough script (target 7 to 8 minutes)

Record the hosted app, not localhost. Open it once a minute before you start so the free Render
instance is awake, and have the repo open in a second tab. Pick a corridor and departure time where
the forecast is not entirely calm if you can (check the heatmap first); if everything is Low, say so
honestly and use the heavy-load preset to show the load rules.

## 0:00 What it is (30 s)
- "This helps a truck driver choose the safest of three routes using weather, load weight and travel
  time. React frontend, Django backend, OpenRouteService for routes and Open-Meteo for weather."
- Show the empty app and the three one-click examples.

## 0:30 Run a trip (1 min)
- Pick Denver to Chicago (or any trip), keep Typical load, 25 mi interval, click **Find safest route**.
- Point out that departure is read in the starting point's time zone.
- While it loads: "It finds the main truck route, then routes through offset waypoints to get genuinely
  different alternatives, because OpenRouteService caps its own alternatives at 100 km."

## 1:30 Results and the recommendation (1.5 min)
- Read the recommendation and its reason: "ranked by Severe miles, then High miles, average risk, then
  time, and it tells you which one decided."
- Walk one route card: distance, drive time, arrival time in the origin's time zone, the bar of miles by
  risk level, and the checkpoint strip.
- Click another route to show it highlights on the map. Click a checkpoint to show the popup: arrival
  time, wind, rain, snow, and why the level was chosen.

## 3:00 The load rules (1 min)
- Switch the load to **Heavy** and re-run. Show the live note: over 30,000 lb wind from 45 mph is No
  Travel, over 40,000 lb wind from 35 mph is Severe.
- Show a checkpoint popup that says "Raised because of the load weight" if one exists.
- Open **How risk is scored** and match the table to the brief.

## 4:00 The forecast heatmap (1.5 min)
- Drag the slider across 0 to 48 hours. "The whole 48 hours arrives in one response, one character per
  hour per point, so scrubbing never touches the network."
- Press play. Show the counts per risk level under the slider changing with the hour.
- Mention weather cells: 0.1 degree, at most 150, along all three routes.

## 5:30 How it is built (1.5 min)
- In the repo: `backend/engine` is pure functions with no I/O. Show `risk.py` and `thresholds.py`.
- "Every threshold boundary and each ranking tiebreaker has a test: 414 backend tests, about 98%
  coverage, plus 90 frontend tests including the slider."
- Show the CI run: tests, `pip-audit`, build, and a Docker smoke test.
- Mention that two code reviews and a security review found real bugs (a dead slider, a rate-limit
  bypass) that were fixed before merge.

## 7:00 Honest limits and what next (45 s)
- Real weather is often calm, so most results read Low.
- ETAs ignore breaks and traffic; alternatives are generated by offset waypoints.
- At scale: Redis for cache and rate limits, then more workers; jobs if analysis got slower.
- "Thanks for watching."

## Checklist before you hit record

- [ ] README has the live URL at the top
